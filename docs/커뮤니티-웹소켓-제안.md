# 커뮤니티 웹소켓 제안 (프론트, 2026-11-03 · 2026-11-04 글 모양 고침)

> **2026-11-04 바뀐 것**: 글이 **제목 + 본문 + 사진**이 됐다(토스증권 앱 커뮤니티처럼 — 글쓰기 화면·글 상세 화면을 만들었다). 아래 `post`에 `title`·`imageUrls`,
> 보내기에 `title`, 글 하나 받기 `GET /api/community/posts/{postId}`, 사진 올리기 경로가 더해졌다. 11-03 모양(제목 없음)으로 와도 프론트는 본문을 제목 자리에 둔다.

프론트가 커뮤니티를 게시판으로 먼저 만들어 두었다(머리글 '커뮤니티' → `/community`, 홈 오른쪽 아래 최신 글 다섯 줄).
지금은 예시 글을 그리고 화면에 "예시"라고 적는다. 보고 있는 동안 예시 새 글이 몇 분마다 들어와 "새 글 N개 보기"가 뜨는 모습까지 목업이다.
아래 모양으로 주면 프론트는 **환경 변수 하나(`VITE_COMMUNITY_WS_URL`)만 넣으면** 붙는다(`src/api/community.ts`). 다르게 줘도 된다 — 그러면 프론트가 그 파일 하나를 맞춘다.

JUBY-BE `feature/websocket/#73`(2026-11-03 확인)은 증권사 실시간 시세용이고 `spring-boot-starter-websocket`·`stomp-websocket`을 들였다.
그래서 같은 스프링 STOMP를 전제로 적었다. 프론트는 라이브러리 없이 STOMP 1.2 프레임(CONNECT·SUBSCRIBE·SEND·DISCONNECT)을 직접 쓴다.

## 연결

- 주소: 예 `wss://api.juby.store/ws` — `registerStompEndpoints`의 엔드포인트. **SockJS 없이 순수 웹소켓**으로 열어 주면 된다(`withSockJS()`를 쓰면 프론트가 붙지 못한다).
- CONNECT 프레임에 `Authorization: Bearer <accessToken>` 머리를 단다(로그인했을 때만). 읽기는 비로그인도 되게, 글쓰기는 로그인만 되게 해 주면 좋다.
- 하트비트는 `0,0`(끄기). 끊기면 프론트가 1·2·4…30초 뒤 다시 붙는다.

## 받기 — `SUBSCRIBE /topic/community`

MESSAGE 본문은 JSON 하나이고 `type`으로 가른다. 모르는 `type`·모양이 틀린 값은 프론트가 버린다.

```json
{ "type": "POST_CREATED", "post": { "postId": 42, "author": "주린이공부중", "stockCode": "005930", "stockName": "삼성전자",
  "title": "백테스트 점수 보는 법", "content": "백테스트 처음 돌려 봤어요.\n점수 보는 법 알려 주실 분?", "imageUrls": ["https://.../a.webp"],
  "createdAt": "2026-11-03T05:12:00Z", "likeCount": 0, "commentCount": 0 } }
{ "type": "POST_UPDATED", "postId": 42, "likeCount": 3, "commentCount": 1 }
{ "type": "POST_DELETED", "postId": 42 }
```

- `createdAt`은 ISO 8601(시간대 포함). 화면은 "12분 전"으로 센다.
- `stockCode`·`stockName`은 종목 없는 글이면 `null`. 있으면 글 머리에 종목 줄(이름 · 그날 등락률 — 프론트가 `GET /api/stocks`에서 붙인다)이 서고 종목 카드 줄에 센다.
- `title`은 40자, `content`는 1000자까지(줄바꿈 그대로). `imageUrls`는 http·https 주소 배열(없으면 빈 배열) — 목록은 첫 장을 미리보기로, 글 상세는 전부 그린다.
- `author`는 별명(이메일·회원 번호를 보내지 않는다).

## 보내기 — `SEND /app/community/posts`

```json
{ "title": "제목(40자까지)", "content": "글 내용(1000자까지, 줄바꿈 포함)", "stockCode": "005930" }
```

서버가 저장한 뒤 `/topic/community`로 `POST_CREATED`를 뿌리면 쓴 사람 화면에도 그 길로 들어온다(프론트는 따로 목록에 끼우지 않는다).
글쓰기 화면은 보낸 뒤 제목·내용이 같은 `POST_CREATED`를 기다려 그 글 상세로 간다(8초 안에 안 오면 목록으로). 사진은 아래 "사진 올리기"가 생기면 `imageUrls`를 더해 보낸다.

## 처음 목록 — REST

웹소켓은 연결한 뒤의 일만 주므로 처음 목록은 따로 받는다: `GET /api/community/posts?stockCode=&page=0` → `{ isSuccess, code, message, result: { posts: [위 post 모양] } }`.
최신순, 20개씩. 목록 API가 생기면 `src/api/community.ts`의 `loadCommunityPosts`를 이 요청으로 바꾼다(지금은 예시 글을 짓는다 — 실제 주소가 있으면 빈 목록).

글 상세를 주소로 바로 열 때(새로고침·공유한 주소): `GET /api/community/posts/{postId}` → `result: post`. 없으면 404.
`loadCommunityPost`가 이 자리다(지금은 예시 글에서 찾는다 — 실제 주소가 있으면 null이라 목록에서 눌러 온 글만 열린다).

## 사진 올리기 — REST(제안)

`POST /api/community/images`(multipart, 로그인) → `result: { url: "https://..." }`. 글쓰기 화면이 사진을 고르는 대로 올려 주소를 받고, 보내기에 `imageUrls`로 싣는다.
한 장 5MB·글 하나에 4장 정도로 막아 주면 좋다. 그때까지 글쓰기 화면의 사진 칸은 잠겨 있고 "준비 중"이라고 적는다.

## 아직 프론트에 없는 것

- 공감 누르기·댓글: 화면은 수만 보인다(누르는 단추를 두지 않았다). 글 상세에 "댓글 N" 구역 자리만 있다. 서버에 경로가 생기면 단추·댓글 목록을 붙인다
  (예: `GET·POST /api/community/posts/{postId}/comments`, `POST·DELETE /api/community/posts/{postId}/likes`).
- 글 지우기·신고: 같은 까닭으로 없다. 이용 안내(오른쪽 칸)는 `src/content/communityRules.ts`에 있다.
