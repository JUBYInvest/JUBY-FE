## 무엇을 했나

2026-11-02에 같은 출발점(`286de21`)에서 두 줄기가 따로 나갔다.

- **이 main**(`abb8fd3`, 운영 중): 결함 수정, 판정을 저장소 `judge/`에 들임, 화면 파일 나누기(훅·부품), 홈 커뮤니티 채팅, 나란한 열의 선 맞추기, 로그인 다시 디자인, 주식 모아보기 배치.
- **개인 저장소 `design/fresh-look`**(`28064fd`): 탭 아이콘, 구역 머리 규격·공용 CSS 모듈, 화면 파일 나누기, 한국 시각 하나로, 화면 전환·스피너.

그냥 합치면 14개 파일이 충돌했다. 대부분은 화면 파일 나누기를 두 번 한 탓이다. 그래서 두 빌드를 같은 가짜 응답으로 띄워 11개 화면을 1440·390px로 나란히 찍었고, 사용자가 화면별로 골랐다.
그 뒤 main에서 새 브랜치를 내어 고른 것만 다시 얹었다.

## 화면 전환을 이렇게 짰다

- **메뉴 막대가 미끄러진다.** 머리글의 연초록 막대가 앞 메뉴 자리·폭에서 누른 메뉴로 옮겨 간다. 막대는 링크마다 그리는 `::before`라서 Web Animations의 `pseudoElement`로 움직인다. 같은 줄의 메뉴끼리만 옮긴다(휴대폰에서는 계정 메뉴가 윗줄에 있다).
- **본문이 떠오른다.** 8px 아래에서 220ms 동안 올라온다. 막대와 같은 때·같은 감속 곡선(`cubic-bezier(0.2, 0, 0, 1)`, `utils/motion.ts`)이라 누른 곳과 바뀐 곳이 한 동작으로 읽힌다.
- **뒤로·앞으로 가기에는 둘 다 걸지 않는다.** 떠났던 자리로 바로 선다(홈은 스크롤까지 되살린다). 처음 들어올 때와 움직임 줄이기 설정에서도 걸지 않는다.
- **화면 묶음을 받는 동안에는 머리글 띠 아래 끝에 연초록 줄이 흐른다.** 150ms가 지나야 보이고, `utils/routeLoading.ts`가 센다.
  - fresh-look은 `Suspense` 빈 자리에 스피너를 뒀는데, 판정을 짜다 보니 **메뉴로 옮길 때는 한 번도 뜨지 않았다**.
  - React Router가 이동을 전환(startTransition)으로 처리해서, 묶음이 올 때까지 앞 화면을 그대로 두기 때문이다. 빈 자리는 주소를 직접 열 때만 보인다.
  - 그래서 `lazy`를 `trackRouteChunk`로 감싸 받는 동안을 세고, 머리글이 그걸 구독한다.
- **스피너**(`components/Spinner`)는 글 한 줄뿐인 자리에 둔다. 홈 시세표·더 불러오기, 백테스트 성향·실행 단추·결과, 뉴스 더 보기, 성향테스트 문항, AI 대화 목록, 로그인 중이다.
