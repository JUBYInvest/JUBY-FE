# 커뮤니티 종목 카드 줄 · 최신/인기 탭 · 종목 검색 (2026-11-04)

## 요청

> 현재 커뮤니티는 전체, 종목 이렇게 되어있어. 2번사진을 최대한 참고하여 현재 왼쪽에 있는 전체/각 종목 선택창을 맨 위에 올려주고,
> 좌우로 스크롤해서 종목을 선택하거나 검색버튼을 통해 종목을 선택할 수 있도록 변경하였으면 좋겠어.
> 또한 2번 사진의 예시대로 인기 탭을 만들어서 인기있는 게시글을 정렬할 수 있도록 해줘.

2번 사진은 토스증권 앱 커뮤니티(제목 줄 검색 아이콘, 홈·인기·보유종목 탭, 종목 카드 줄 — 로고·이름·새 글 수, 그 아래 글).

## 바꾼 것

- **카드**: 첫 글자 동그라미(글 줄 별명 동그라미와 같은 모양 — 로고가 없는 서비스라 사진 2의 로고 자리), 종목 이름 두 줄까지, "글 N".

# 2부 — 글 구조(제목·본문·사진), 글쓰기 화면, 글 상세, 글 머리 등락률

## 요청

> 테스팅 완료 후 다음 사진처럼 커뮤니티 글쓰기 개념으로 생각해서 프로그래밍이 되었는지 확인해줘

사진은 토스증권 앱 커뮤니티 **인기** 탭(이번 주 인기글 · 실시간 인기 종목, 글마다 종목 로고·이름·등락률 → 굵은 제목 → 본문 두 줄 + 사진 → 공감·댓글·시각·⋯, 떠 있는 "글쓰기").

## 확인한 것(1부 커밋 4629ffa 기준) — 글쓰기 개념이 아니었다

| 사진 | 4629ffa |
| --- | --- |
| 글 = 굵은 **제목** + 본문(두 줄에서 자름) | 본문 한 칸, 전부 보임 |
| **사진** 첨부 | 없음(글 모양에 사진 칸이 없다) |
| 종목 줄에 **그날 등락률** | 본문 앞 종목 이름(초록 링크)뿐 |
| 떠 있는 **글쓰기 단추 → 글쓰기 화면** | 목록 위 한 줄 입력칸(줄바꿈 불가, 종목 = 고른 카드), 목업이라 잠김 |
| 인기 탭 안 이번 주 인기글 / 실시간 인기 종목 | 인기 = 전체 글 공감 순 |
| 글을 누르면 **글 상세**(댓글) | 글 상세 없음 |

서버에 건넨 글 모양 제안(`docs/커뮤니티-웹소켓-제안.md`)에도 제목·사진이 없었다. 차이를 알리고 범위를 물었다 — 사용자 답: **글 머리 등락률, 제목+본문 글과 글쓰기 화면, 글 상세**
(인기 탭 안 두 갈래는 고르지 않음), 올리기는 "아직 안 올림".

## 바꾼 것

- **글 모양**(`api/community.ts`): `title`(없이 오면 null — 본문을 제목 자리에), `imageUrls`(http·https만, `safeLink`), 보내기 `CommunityDraft { title, content, stockCode }`,
  한도 `COMMUNITY_LIMITS` 제목 40자·내용 1000자, 글 하나 받기 `loadCommunityPost`(제안 `GET /api/community/posts/{postId}` 자리 — 지금은 예시 글에서).
  예시 글 13개에 제목을 달고 한 글(9번)에 사용설명서 3장 이동평균 교차 그림을 붙였다.
- **글 줄**(`CommunityPosts`): 종목 줄(첫 글자 동그라미 · 이름 · 등락률) → 굵은 제목 17px → 본문 두 줄 + 오른쪽 사진 88px(600px 이하 72px) → 공감·댓글 | 별명 · 몇 분 전.
  줄 어디를 눌러도 글 상세(제목 링크 `::after`). 홈은 별명 · 시각 / 제목 한 줄 / 종목 · 본문 한 줄.

- **글 상세** `/community/{postId}`: "‹ 커뮤니티로 돌아가기" → 제목(화면 제목) → 두 열(종목 줄·쓴 사람·본문 전부·사진·공감/댓글 수·"댓글 N" 자리 | 이용 안내).

# 3부 — 모바일 점검과 다듬기

## 요청

> 모바일 버전에서도 대응되는지 확인하고, /frontend-design:frontend-design 스킬을 써서 유려하게 만들어줘.

## 확인한 것(2부 커밋 195ca06, 375×812 손가락 화면)

세 화면(목록·글 상세·글쓰기) 모두 가로 넘침 0, 떠 있는 "글쓰기"는 지수 띠 위, 앞·뒤 단추는 숨는다 — **깨지는 곳은 없었다.** 다듬을 곳:

- 글쓰기의 **올리기가 첫 화면 밖**(1,054px — 화면 812px)이라 내용을 쓰는 동안 보이지 않았다. 몇 자 썼는지가 칸마다 아래 한 줄을 더 차지했다.
- 글 상세 머리에 **종목 줄(동그라미 · 초록 이름)과 쓴 사람 줄(동그라미 · 별명)이 같은 꼴로 겹쳐** 섰다. 종목 링크는 이름 글자만 눌렸다.
- 줄 전체가 링크인 글 줄을 눌러도 **눌렸다는 답이 없었다**(브라우저 기본 회색 상자는 제목 글자만 덮는다).
- 화면 끝에 반쯤 걸친 카드를 누르면 골라지기만 하고 카드는 반쯤 잘린 채였다. 카드에는 글 수뿐이라 어느 종목이 움직였는지는 글을 내려 봐야 알았다.

## 디자인 계획(스킬 — 앱 규칙이 먼저)

색·글꼴은 2026-10-30 규칙 그대로(흰 바탕, 먹 #111827, 보조 #5f6b66, 선 #e4e8e6, 초록 #15803d는 행동·선택에만, 빨강·파랑은 등락에만, Pretendard).
한 곳에만 힘을 준다 — **종목 카드 줄을 "대화의 시세판"으로**: 카드마다 그날 등락률을 싣고, 누르면 들어가는 답을 준다. 나머지는 조용히 간격·위계·누름 답만.
계획을 다시 보고 뺀 것: 스크롤하면 "글쓰기"가 동그라미로 줄어드는 것(흔한 기본값이고 공용 단추 값을 덮어써야 한다), 카드 줄 끝 흐림(장식 — 화면 끝까지 미는 카드가 이미 밀 수 있음을 보인다).

## 바꾼 것

- **종목 카드**(`CommunityPage`): 아래 줄 "글 N" | 그날 등락률(글 머리와 같은 값·색, 전체 카드는 없음). 누르는 동안 0.97로 들어간다. 화면 끝에 걸친 카드를 누르면 줄 안에서만 밀어 다 보인다
  (페이지는 움직이지 않는다). 탭·카드·검색으로 바뀐 목록은 0.22초 떠오른다(화면 전환과 같은 곡선, 처음 그릴 때는 없다). 움직임 줄이기면 셋 다 없다.
- **누름 답**(`CommunityPosts`·`CommunityPostPage`): 손가락 화면에서 글 줄·종목 줄을 누르는 동안 옅은 면, 900px 이하는 본문 좌우 여백만큼 같은 색 그림자로 화면 끝까지. 첫 글자 동그라미는 그동안 흰색.
- **글 상세 종목 줄**: 먹 선 바로 아래 36px 동그라미 | 이름 · 등락률 / "N월 N일 종가 기준" | ›, 가는 선으로 쓴 사람과 가른다. 줄 어디를 눌러도 종목 상세(이름 링크의 `::after`), 본문과 같은 760px까지.

- **글쓰기**: 몇 자 썼는지를 칸 이름 줄 오른쪽으로. 취소 | 올리기 줄이 화면 아래 지수 띠 바로 위에 붙어 따라온다(흰 바탕 + 가는 선, 끝까지 내리면 제자리).

# 4부 — 종목이 많을 때 카드 줄, 당겨서 새로고침

## 요청

> ㅇㅇ 좋은데, 커뮤니티 종목이 다양해지면 좌우스크롤도 정상적으로 되는지 확인해줘. 또한 글을 위쪽 방향으로? 잡아당겼을 때 새로고침이 되어 새 글이 나오는 것도 반영해줘.

## 종목이 많을 때 카드 줄 — 확인(3부 커밋 4ef6e66)

예시 글은 다섯 종목뿐이라, 웹소켓 빌드에 가짜 서버를 붙여 **30종목 글 40개**(`src/api/stockList.ts` 앞 30종목 — 한화에어로스페이스·LG에너지솔루션처럼 긴 이름 포함)를 밀어 넣고 쟀다(`judge/community.mjs` B19).

- **휴대폰(375 손가락)**: 카드 31장이 한 줄, 페이지 가로 넘침 0. 손가락으로 밀면 줄만 밀리고(페이지 x·y 그대로) 스물몇 번 밀어 끝(3,741px)에 닿으면 마지막 카드가 다 보인다(235~359px).
  줄 위에서 위아래로 밀면 페이지가 내려간다(줄이 세로 몸짓을 붙잡지 않는다). 끝 카드를 누르면 그 종목 글만 나오고 줄은 제자리.
- **마우스(1440)**: 뒤 단추 네 번이면 끝, 마지막 카드가 줄 안에 다 보이고 뒤 단추가 사라진다. **키보드**: Tab 30번으로 끝 카드까지 따라가며 줄이 밀린다.
- **빠져 있던 것 하나**: 줄 끝까지 민 뒤 더 미는 몸짓이 페이지로 번지는 것을 막지 않았다(`overscroll-behavior-x` 기본값). 맥 트랙패드에서는 그게 브라우저 "뒤로 가기"가 된다 —
  판정 브라우저에서는 주소가 그대로였으니 미리 막는 것이다. 카드 줄에 `overscroll-behavior-x: contain`.

## 당겨서 새로고침 — 만든 것

손가락 화면에서 커뮤니티 목록 **맨 위를 끌어내리면** 새 글을 받는다(토스증권 앱·대부분의 앱과 같은 몸짓). 마우스·키보드는 지금처럼 "새 글 N개 보기".

- **모습**: 끌어내린 만큼(손가락 거리의 절반, 112px까지) 본문이 내려오고 벌어진 자리 가운데에 아래 화살표. 64px을 넘기면 화살표가 위로 뒤집혀 "놓으면 받는다"를 알린다.
  놓으면 56px에 멈춰 도는 고리(너무 빨리 끝나도 0.6초는 보인다) → 결과 한 줄("새 글 1개" · "새 글이 없어요" · 종목을 고른 채면 "삼성전자 새 글 1개"·"전체에 새 글 2개")을 1초 → 제자리.
  (5부에서 결과 한 줄을 걷었다 — 사용자 요청.)
  새 글은 목록 맨 위에 서고 목록이 잠깐 떠오른다(3부의 바뀐 목록 움직임). 덜 당기면 그냥 돌아간다. 결과는 읽어 주는 쪽에도 알린다(`role="status"`). 움직임 줄이기면 미끄러지지 않고 곧바로 선다.
- **무엇을 받나**(`useCommunityFeed refresh`): 쌓여 있던 새 글 + 지금 받아 오는 새 글 + 처음 목록을 다시 받아(`loadCommunityPosts`) 목록에 없던 글. 지금 받아 오는 새 글은
  연결이 정한다(`CommunityConnection.pullNow`) — **목업은 다음 예시 새 글을 곧바로 내준다**(40초·70초를 기다리지 않는다, 그다음 글 간격은 다시 센다. 셋을 다 받으면 "새 글이 없어요").
  실제 연결은 서버가 밀어 주므로 빈 목록이고, 처음 목록 API(제안 `GET /api/community/posts`)가 생기면 다시 받은 목록에서 빠진 글을 채운다.
- **몸짓 가르기**(`hooks/usePullToRefresh`): 페이지 맨 위에서 닿았을 때만 듣고, 처음 8px이 옆쪽(카드 줄 밀기)이거나 위쪽(내려 읽기)이면 손대지 않는다. 글자 칸·검색 후보 안은 뺀다.
  당기는 동안은 페이지가 움직이지 않는다(그 손가락의 기본 동작을 막는다). 손가락을 따라가는 동안은 React를 다시 그리지 않고 CSS 변수(`--pull`)만 바꾼다.
- **브라우저 자체 당겨서 새로고침을 끈다** — 안드로이드 크롬은 맨 위를 끌어내리면 페이지 전체를 다시 읽는다(목록·고른 종목이 처음으로 돌아가고 묶음을 다시 받는다). 커뮤니티 목록에 있는 동안만
  `html`에 `overscroll-behavior-y: contain`을 걸고 떠나면 되돌린다. 아이폰의 위쪽 출렁임도 같이 꺼진다.

**B로 바꿨다.** 탭 줄은 구역 제목 줄과 같은 46px·바닥선 맞춤이지만 선이 1px 가는 선이다(`section head`를 composes하면 2px 먹 선을 덮어써야 해 따로 적었다 — 공용 모듈 규칙).
