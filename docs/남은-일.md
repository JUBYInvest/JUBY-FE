# 남은 일

코드로 확인했지만 아직 고치지 않은 것과, 사용자가 정하기 전에는 손대지 않는 것.
**코드를 고치기 전에 먼저 본다.** 고친 항목은 지우고, 새로 찾은 문제는 여기에 적는다.
ID(B-6, H-4 …)는 [테스트-결과-2026-09-23.md](테스트-결과-2026-09-23.md)의 항목 번호다.

## 고치지 않은 것

1. **로그인은 운영에서 된다.** 2026-10-06 사용자가 운영(`https://juby-fe.vercel.app`)에서 로그인이 잘 된다고 확인했다.
   로그인 상태의 세부 흐름(성향 404, 저장 실패·다시 저장, 관심종목, 로그인 뒤 돌아갈 곳, 로그아웃, 내 정보 수정 G-2·G-4,
   AI 새 대화 G-3, 토큰 재발급)을 하나씩 돌려 본 기록은 아직 없다 — 쓰다가 어긋나면 여기 적는다.
   사파리는 다른 사이트 쿠키를 막아 재발급이 안 될 수 있다(아래 "백엔드·배포에 넘길 것" 5번 덧붙임).
   배포 중계(Vercel)가 오래 걸리는 AI 답을 어디까지 기다리는지도 재 보지 않았다 — 프론트는 제한 없이 기다린다("그만 기다리기"로 끊을 수 있다).
2. **백테스트 수익률 0%(백엔드)**: 기간 끝 보유 포지션 미청산 + 비율 컬럼 소수 둘째 자리(AI 요약 단위는 2026-09-30 `46e1ee3`에서 고쳐짐).
   홈 대장주 API(`leading-stocks`)의 전략 수익률도 같은 프리셋에서 온다 — 2026-10-04 실서버는 매매 0·1회 종목이 0.0%였다.
   카드는 그래프를 되살리며 전략 수익률을 적지 않게 됐다(대장을 고르는 근거로만 쓰인다).
   2026-10-22 백엔드 PR #110(지표 워밍업 봉, 즉석 실행 API)은 "거래 0회"를 줄이지만 끝의 열린 포지션은 여전히 청산하지 않는다(2026-10-29 소스 확인).
   원인과 수정안은 CLAUDE.md "백엔드 사정 > 백테스트". 백엔드가 고치고 운영 DB에 ALTER + 프리셋 배치를 다시 돌리면
   프론트는 고칠 것 없이 맞게 보인다. 그 전까지 거래 0회로 끝까지 들고 있던 결과는 화면이 임시 안내로 알린다
   (`isHeldToEnd`) — **백엔드가 고치면 그 안내를 지운다.** 끝난 거래 뒤에 다시 사서 들고 있는 결과는 프론트가 가려내지
   못해 수익률이 덜 잡힌 채로 안내 없이 보인다. 비율이 소수 둘째 자리로 잘려 "23.00%"처럼 정밀해 보이는 것도 그대로다.
3. 비로그인 성향테스트는 문항 GET이 401이라 늘 임시 7문항이다. 2026-10-05부터 안내가 "로그인하면 정식 문항으로 검사하고 결과를
   저장해요"(로그인 링크)이고, 서버가 정말 실패했을 때만 "서버 문항을 불러오지 못해"다(`fallbackReason`). 백테스트 기간 옵션의 401은
   더 이상 "서버 목록을 받지 못해…"로 알리지 않는다(실행하면 결과 자리가 로그인 안내, G-5). 비로그인을 어떻게 할지는 아래 "결정 대기".

   (AI 대화방의 제목 바꾸기·지우기는 2026-09-30에 사이드바에 붙였다 — CLAUDE.md "AI 대화방".)
