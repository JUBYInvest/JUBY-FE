# 남은 일

코드로 확인했지만 아직 고치지 않은 것과, 사용자가 정하기 전에는 손대지 않는 것.
**코드를 고치기 전에 먼저 본다.** 고친 항목은 지우고, 새로 찾은 문제는 여기에 적는다.
ID(B-6, H-4 …)는 [테스트-결과-2026-09-23.md](테스트-결과-2026-09-23.md)의 항목 번호다.

## 고치지 않은 것

1. **로그인 상태의 수정은 실제 서버로 확인된 적이 없다**(성향 404, 저장 실패·다시 저장, 토큰 규칙, 관심종목, 진입 시 401,
   로그인 뒤 돌아갈 곳). 백엔드 OAuth 리다이렉트가 붙으면 이 흐름부터 실제로 돌려 본다.
2. **백테스트 비교 일부 실패 때 결론 문장**: 다섯 중 일부를 못 받으면 순위 아래 "N개 전략은 불러오지 못했어요"를 적지만,
   위의 "그 결과 ○○는 △△에게 가장 잘 맞는 종목이에요"는 받은 것만으로 낸 1등을 그대로 단정한다(F-14 범위 밖).
3. 다른 탭에서 로그아웃하면 백테스트의 성향 문구는 지워지지만, 성향에 맞춰 미리 골라 둔 전략은 선택칸에 남는다(F-21 범위 밖).
4. 응답의 빈 값 중 화면에 맡긴 자리가 남아 있다(코드에서 `unchecked(`로 찾는다). 전부 포맷 함수가 "-"로 적거나 화면이
   쓰지 않는 값이다 — 2026-09-27에 화면이 받아내지 못하던 자리(목록 행 코드·이름, 성향 문항·저장 응답, 뉴스 전체 개수)는 막았다.
5. **백테스트 수익률 0%(백엔드)**: 기간 끝 보유 포지션 미청산 + 비율 컬럼 소수 둘째 자리 + AI 요약 단위.
   원인과 수정안은 CLAUDE.md "백엔드 사정 > 백테스트". 백엔드가 고치고 운영 DB에 ALTER + 프리셋 배치를 다시 돌리면
   프론트는 고칠 것 없이 맞게 보인다. 그 전까지 거래 0회로 끝까지 들고 있던 결과는 화면이 임시 안내로 알린다
   (`isHeldToEnd`) — **백엔드가 고치면 그 안내를 지운다.** 끝난 거래 뒤에 다시 사서 들고 있는 결과는 프론트가 가려내지
   못해 수익률이 덜 잡힌 채로 안내 없이 보인다. 비율이 소수 둘째 자리로 잘려 "23.00%"처럼 정밀해 보이는 것도 그대로다.

## 결정이 먼저 필요한 것

사용자가 정하기 전에는 구현하지 않는다.

2026-09-27 사용자가 정해 처리한 것: 성향→전략 자동 선택(B-6)은 지금 방식 유지(`feat/backtest-strategy-cards`는 그대로 둠),
백테스트 중복 요청(B-3) 합치기, 비교 동점은 공동 1위, 홈 카드는 10분, 상세 1분·뉴스 10분 캐시, AI "그만 기다리기",
로그인 뒤 원래 자리로, 범위 밖 성향 점수(W-FN-1)는 결과를 내지 않음, 머리글 `번호`→`종목코드`(H-4), `nanoid`는
lockfile만 갱신, 검증 스크립트는 저장소에 두지 않음. 자세한 건 [수정-결과-2026-09-27.md](수정-결과-2026-09-27.md) "추가 작업".

- Vercel이 `http://` 외부 주소로의 rewrite를 허용하는지는 실제 배포 전에는 확인할 수 없다(로컬 흉내로는 통과).
  같은 중계가 오래 걸리는 AI 답을 어디까지 기다리는지도 배포에서 본다 — 프론트는 제한 없이 기다린다("그만 기다리기"로 끊을 수 있다).
- **휴대폰 홈 시세표에서 거래대금 순으로 되돌아가기**: 600px 이하에서는 거래대금 머리가 숨어, 다른 정렬로 바꾼 뒤
  거래대금 순으로 돌아갈 방법이 새로고침뿐이다. 2026-09-26에 정렬 기준을 글로만 알리기로 정했다(선택칸은 두지 않음).
