# 남은 일

코드로 확인했지만 아직 고치지 않은 것과, 사용자가 정하기 전에는 손대지 않는 것.
**코드를 고치기 전에 먼저 본다.** 고친 항목은 지우고, 새로 찾은 문제는 여기에 적는다.
ID(B-6, H-4 …)는 [테스트-결과-2026-09-23.md](테스트-결과-2026-09-23.md)의 항목 번호다.

## 고치지 않은 것

1. **응답의 빈 값을 아직 막지 않은 자리(F-15에서 드러남).** 응답 타입을 서버 스키마대로 풀었을 때 `tsc`가 짚은 38곳 중,
   화면이 받아내지 못하는 곳이다. 코드에서 `unchecked(`로 찾는다. 자세한 표는
   [수정-결과-2026-09-27.md](수정-결과-2026-09-27.md) "F-15에서 드러난 자리".
   - **종목 목록 한 행의 `stockName`이 `null`이면 검색창에 글자를 치는 순간 화면 전체가 오류 화면이 된다**
     (`normalize(null)`, 2026-09-27 실행으로 확인). 홈 검색과 백테스트 종목 검색 둘 다 같은 함수다. `stockCode`가 `null`이어도
     같은 자리에서 던진다(코드 판독).
   - 관심종목 한 행의 `stockCode`·`stockName` 빈 값 — 링크가 `/stocks/null`, 해제 요청이 `/like-stocks/null`(코드 판독).
   - 성향 문항·보기의 번호·글·점수 빈 값 — 보기 번호가 둘 다 `null`이면 한 번 누를 때 둘이 같이 골라지고, 점수 `undefined`면
     합이 NaN이 된다(코드 판독). 서버 문항은 DB 10개로 고정이라 닿을 가능성은 낮다.
   - 성향 결과 POST의 `personalityName`이 `null`이면 결과 카드의 이름 자리가 빈다(설명은 대체 문구). 본문 자체가 `null`이면
     구조 분해에서 던져 "저장하지 못했어요"가 뜨는데 서버는 이미 저장했다 — F-1과 같은 결(코드 판독).
   - 뉴스 `totalCount`가 비면 "더 보기"가 숨는다(코드 판독).
2. **로그인 상태의 수정은 실제 서버로 확인된 적이 없다**(성향 404, 저장 실패·다시 저장, 토큰 규칙, 관심종목, 진입 시 401).
   백엔드 OAuth 리다이렉트가 붙으면 이 흐름부터 실제로 돌려 본다.
3. **백테스트 비교 일부 실패 때 결론 문장**: 다섯 중 일부를 못 받으면 순위 아래 "N개 전략은 불러오지 못했어요"를 적지만,
   위의 "그 결과 ○○는 △△에게 가장 잘 맞는 종목이에요"는 받은 것만으로 낸 1등을 그대로 단정한다(F-14 범위 밖).
4. 다른 탭에서 로그아웃하면 백테스트의 성향 문구는 지워지지만, 성향에 맞춰 미리 골라 둔 전략은 선택칸에 남는다(F-21 범위 밖).
5. 백테스트 비교가 동점이면 번호 작은 성향을 "가장 잘 맞는"으로 단정한다(2026-09-27 지시서 C부 — 결정 먼저).
6. **백테스트 수익률 0%(백엔드)**: 기간 끝 보유 포지션 미청산 + 비율 컬럼 소수 둘째 자리 + AI 요약 단위.
   원인과 수정안은 CLAUDE.md "백엔드 사정 > 백테스트". 백엔드가 고치고 운영 DB에 ALTER + 프리셋 배치를 다시 돌리면
   프론트는 고칠 것 없이 맞게 보인다. 그 전까지는 거래 0회 경고가 보유 포지션이 있는 결과에도 뜬다.

## 결정이 먼저 필요한 것

사용자가 정하기 전에는 구현하지 않는다.

- **성향→전략 자동 선택(B-6)**: 이 브랜치의 `dae25f3`이 로그인 시 성향에 맞는 전략을 미리 고르고 결과 문장이
  "나는 위험중립형, 여기에 맞는 …"을 말한다(`BacktestPage`의 추천 effect). 그걸 뺀 `0cf23ba`는
  `feat/backtest-strategy-cards`에만 있어 두 브랜치가 반대 결정을 들고 있다. 합치기 전에 방침을 정한다.
- **백테스트 중복 요청(B-3)**: 한 번 누르면 preset 6건이고, 고른 전략이 비교용 5건과 겹쳐 같은 요청이 두 번 나간다.
  B-6과 엮여 있다. 종목이 같으면 비교용 5건(1년 기준)은 늘 같은데, 기간이나 전략만 바꿔 다시 실행해도 매번 다시 받는다
  (2026-09-27 확인). 홈에서 받은 종목 목록도 백테스트 화면이 따로 다시 받는다(둘 다 DB만 읽어 가볍다).
- **홈 카드 재요청**: 홈에 올 때마다 카드 3건(증권사 3회)이 다시 나간다. 캐시 기간을 정해야 한다.
- **종목 상세·뉴스 응답 캐시**: 같은 종목을 다시 열 때 기다리지 않게 하려면 캐시 기간을 정해야 한다.
  상세의 현재가는 실시간이고, 뉴스는 백엔드가 매달 1일에 새로 넣는다. 한 화면 안에서 뉴스 정렬을
  최신순→관련도순→최신순으로 오가도 이미 받은 첫 페이지를 다시 받는다(서버가 요청마다 Pinecone 검색).
- **홈 시세표 첫 열 머리글 `번호`(H-4)**: 값은 종목코드다. 일부러 둔 표기라 사용자가 정할 때까지 둔다.
- **범위 밖 성향 점수(W-FN-1)**: 합이 10~90을 벗어나면 서버는 예외를 던지는데 `scoreToPersonality`
  (`utils/personality.ts`)는 결과를 낸다(9→안정형, 91·NaN→공격투자형). 실제 10문항으로는 범위 밖이 나오지
  않고 NaN은 보기가 빈 문항에서만 생긴다.
- **`nanoid` 취약점(W-B-4)**: vite → postcss 경로의 high 1건. 개발 의존성이라 번들엔 없다. 고치려면
  `package.json`을 건드려야 한다.
- Vercel이 `http://` 외부 주소로의 rewrite를 허용하는지는 실제 배포 전에는 확인할 수 없다(로컬 흉내로는 통과).
  같은 중계가 오래 걸리는 AI 답을 어디까지 기다리는지도 배포에서 본다 — 프론트는 제한 없이 기다린다.
- 검증 스크립트를 저장소에 둘지(CLAUDE.md "브라우저로 검증하는 법").
- **휴대폰 홈 시세표에서 거래대금 순으로 되돌아가기**: 600px 이하에서는 거래대금 머리가 숨어, 다른 정렬로 바꾼 뒤
  거래대금 순으로 돌아갈 방법이 새로고침뿐이다. 2026-09-26에 정렬 기준을 글로만 알리기로 정했다(선택칸은 두지 않음).
