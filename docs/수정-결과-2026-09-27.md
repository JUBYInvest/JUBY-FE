# D부. 백엔드·배포에 넘길 것 (지시서 그대로 옮김 + 근거)

1. **로그인 리다이렉트**: `OAuth2SuccessHandler`가 토큰을 JSON으로 쓰고 끝난다. 프론트 `/oauth/callback?accessToken=&refreshToken=`으로
   보내야 로그인 흐름 전체가 실제 서버로 검증된다. 근거: 이번 B부의 로그인 상태 판정(F-3·F-12·F-21 등)은 전부 가짜 토큰 + 가로챈 응답이다.
2. **평문 HTTP**: `vercel.json`이 `/api/*`를 `http://3.35.191.42:8080`으로 중계하고, 소셜 로그인 시작도 `http://` 주소다
   (`LoginPage.tsx`, `.env.example`). 리다이렉트가 붙으면 토큰이 담긴 주소가 평문으로 오간다. HTTPS 도메인이 필요하다.
3. `POST /api/auth/reissue`·`/logout` 컨트롤러 없음 — 토큰이 만료되면 다시 로그인하는 수밖에 없다(F-3은 그 경험을 덜 거칠게 할 뿐이다).
4. `POST /api/personality-tests`를 토큰 없이 부르면 NPE로 500(permitAll).
5. 백테스트 축 점수를 응답에 담아 주면 `calculateAxisScores`(F-2에서 고친 곳)를 지운다.
6. **백테스트 수익률 0%**(2026-09-27 진단, CLAUDE.md "백엔드 사정 > 백테스트"): ① 기간 끝에 들고 있는 포지션을 청산하지 않아
   `NetReturnCriterion`·`getPositionCount`가 0으로 잡는다 ② `BacktestPresetResult`의 BigDecimal이 기본 `numeric(38,2)`라 0.4%가 0.00으로
   저장된다 ③ AI 요약의 비율 단위. 근거: ta4j 0.22.5로 같은 기준을 돌린 재현(120봉, 10번째 봉에 사고 파는 조건이 한 번도 안 맞음: 청산 없음 → 거래 0회·누적수익률 0.0000·MDD 0.3462,
   마지막 날 청산 → 거래 1회·누적수익률 0.0824 / 0.4% 번 거래 1회 → 누적수익률 0.0040이 DB에 0.00으로 저장).
   백엔드 수정안은 `~/juby-be-backtest-fix`(브랜치 `fix/backtest-open-position-and-scale`, 커밋 안 함)에 있다.
   운영 DB는 `ddl-auto: update`가 기존 열의 자릿수를 바꾸지 않으므로 `ALTER TABLE … DECIMAL(19,6)` 후 프리셋 배치를 다시 돌려야 한다.
