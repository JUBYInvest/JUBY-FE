## 1. 결함: 다른 화면에 다녀오면 휴대폰 제목·상세 단추 크기가 바뀌었다

공용 CSS 모듈(buttons·section)은 그걸 쓰는 화면 묶음마다 한 벌씩 들어온다. 화면 CSS가 가져온 값을 같은 속성으로 다시 적으면, 공용 모듈 한 벌이 그 뒤에 붙는 순간 공용 값이 이긴다. 2026-11-02 로그인 단추 L10과 같은 까닭이다.
판정은 `judge/repro.mjs`에 S1~S7로 더했다. 처음 연 때와 다른 화면에 다녀온 뒤를 견주고, 제목은 화면 CSS가 정한 값(24px)인지도 본다. 고치기 전 4 PASS / 5 FAIL에서 9 PASS / 0 FAIL이 됐다.

|---|---|---|
| S1·S4 휴대폰 AI·마이페이지 화면 제목 | 처음부터 28px(24px로 적혀 있었다) | 24px |
| S2·S3 휴대폰 백테스트·사용설명서 화면 제목 | 처음 24px, 다른 화면에 다녀오면 28px | 24px 그대로 |

- 화면 제목: 900px 이하 24px을 공용 규격(`section.module.css pageTitle`) 한 곳에 두고, 네 화면이 미디어 쿼리로 적던 줄을 걷었다. 사용설명서는 601~900px에서도 24px이 된다(다른 화면과 같다 — 예전엔 600px 이하만 줄였다).
- 단추: `buttons.module.css` md가 높이·안 여백을 변수(`--button-height`·`--button-padding-x`)로 받고, 상세는 변수만 준다.
- 물어서 찾기 단추의 최소 높이(한 줄 flex라 입력칸 높이로 늘어난다)와 마이페이지 링크 hover 색(공용과 같은 값)도 걷었다.

## 3. 일부러 모으지 않은 것

- **등락 글자색(`.up`·`.down`·`.flat`, 여섯 파일).** 그 글자에 화면 CSS가 다른 색을 주는 클래스가 함께 붙는 곳이 있다(상세 "보합은 검은색" 주석). 공용 모듈로 옮기면 1과 같은 까닭으로 색이 뒤집힌다. 판정은 JS 쪽에서 이미 한 곳(`rateTone`)이다.
- **마이페이지 투자유형·내 정보의 "불러오지 못했습니다" 안내.** 마크업은 비슷하지만 모양이 다르다(왼쪽 정렬 옅은 면 / 가운데 큰 여백). 합치면 화면이 바뀐다.
- **AI 답변 뼈대(`pulse`).** 말풍선 모양 뼈대라 반짝임(`shimmer`)과 다르다(2026-11-02 결정 그대로).

## 4. 판정 도구: 바깥 글꼴 때문에 판정이 띄엄띄엄 멈췄다

첫 회 전체 판정에서 ui(4묶음)·backtest·feature·market이 화면을 열다(`page.goto` 4~5초) 멈췄다. 판정이 실패한 게 아니라 시작을 못 한 것이다.
같은 빌드로 다시 돌리면 통과했다. 2026-11-02 기록에도 "바깥 글꼴 CDN이 늦으면 가끔 멈춘다, 다시 돌린다"로 적혀 있었다.

- **원인:** 글꼴 CSS(jsdelivr Pretendard·Google Fonts Michroma)가 첫 그림을 막아, `domcontentloaded`가 CDN 응답을 기다린다. 여섯 번 재니 평소 0.3초, CDN이 늦은 회차에는 1.4초였다(CDN 응답 1.1~1.4초). 더 늦으면 판정의 4~5초 한도를 넘는다.
- **고침:** `judge/mock.mjs`가 글꼴을 처음 한 번만 Node fetch로 받아 `judge/.cache/fonts`(.gitignore)에 담고, 다음부터 거기서 준다. 열쇠는 주소 + user-agent(Google Fonts CSS가 브라우저마다 다르다)이고, 못 받으면 예전처럼 망으로 보낸다.
- **결과:** 화면 열기 0.07초, 글꼴은 Pretendard·Michroma 그대로다. 다시 돌린 전체 판정에서 멈춘 판정이 없다.
- 실행 스크립트(세션 임시 폴더)가 실패한 판정의 기록을 "skip"으로 덮어쓰던 것도 고쳤다(첫 회 market 기록이 그렇게 지워졌다).
